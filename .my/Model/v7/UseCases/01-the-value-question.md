# The Value Question

Before assessing whether this model is worth continuing, it is worth being precise about what would count as an answer. "Is it useful?" is too vague to be decidable, and a framework can always be made to sound useful by describing what it covers rather than what it changes.

## Four tests

A framework has value if it passes these. They are ordered by how hard they are to pass.

### Test 1 — The decision test

**Does anyone do anything differently because of it?**

Not *think* differently — do. A framework that produces recognition and no behavioural change is entertainment. Recognition feels like value because it feels like insight, and it is the most common way an unhelpful framework survives.

Applied concretely: for each scenario in [04-individuals.md](04-individuals.md) through [07-coaches-and-clinicians.md](07-coaches-and-clinicians.md), the question is what action changed, not whether the description rang true.

### Test 2 — The counterfactual test

**What would have happened without it?**

Most of what a good framework says, a thoughtful person arrives at eventually. The relevant value is the difference: arriving faster, arriving more reliably, arriving when not especially thoughtful, or arriving at something that would not have been reached at all.

This test is where frameworks usually lose most of their claimed value, and it is the one most often skipped. A useful discipline is to ask what a competent, experienced practitioner with no framework would have done in the same situation.

### Test 3 — The alternative test

**Is there something better already?**

If an established, evidence-backed construct covers the same ground, the model should defer to it rather than compete. This is the subject of [03-prior-art.md](03-prior-art.md), and it turns out to matter a great deal here.

### Test 4 — The net-harm test

**Does it cause more damage than it prevents?**

An unvalidated framework applied to people has failure modes that a purely academic framework does not. Labelling, misclassification with consequences, and false confidence are real costs and have to be subtracted, not footnoted. See [08-harms-and-net-value.md](08-harms-and-net-value.md).

## The specific trap this model is exposed to

**Expressiveness is not evidence.**

The model's descriptions are rich, well-written, and cover a wide range of human responses. Almost any professional can be made to fit one of them. This produces a powerful and misleading experience: a reader recognises themselves, concludes the model is accurate, and the recognition is taken as confirmation.

It is not confirmation. A framework that fits everyone predicts nothing. Horoscopes pass the recognition test every day.

The test that separates a useful framework from an expressive one is whether it ever says *no*. Concretely:

- Does it identify cases it does not describe?
- Does it distinguish between two people who look similar, in a way that leads to different actions?
- Does it rule anything out?

The model does attempt all three — the scope limits, the confusable-pair diagnostics, the "no good fit" requirement in the classifier. Whether the attempt succeeds is exactly what the discriminability study in [Plans/03-cheap-evidence.md](../Plans/03-cheap-evidence.md) would establish, and it remains unrun.

**Until that study is run, the honest position is that nobody knows whether the model discriminates or merely describes.** That uncertainty should weigh on every value claim in these documents.

## What good value would look like here

If the model has genuine value, specific things should be observable. These are stated in advance so the assessment is not retrofitted.

| Signal | Why it would count |
| --- | --- |
| A practitioner uses it, then uses it again unprompted | Second use is the real test. First use can be curiosity |
| Someone changes a rollout, workflow, or allocation decision because of it | A concrete decision changed |
| Someone reports it stopped them doing something they were about to do | Prevention is easier to attribute than causation |
| Two people who previously talked past each other reach agreement using its vocabulary | The vocabulary claim, tested |
| A case appears that the model clearly does not describe, and this is noticed | Evidence the model discriminates rather than absorbs |

| Absence | What it would mean |
| --- | --- |
| Everyone finds it interesting, nobody uses it twice | Recognition without utility. The most likely failure |
| Every case fits comfortably | The expressiveness trap, confirmed |
| It is only ever used by its author | The framework is legible only to the person who built it |
| It is used to justify decisions already made | Authority laundering. Actively harmful |

The first row of the second table is the outcome to watch for hardest, because it is both the most likely and the easiest to mistake for success. Positive verbal feedback about a framework is nearly worthless as evidence. People are polite about frameworks.

## The asymmetry between vocabulary and diagnosis

The model does two quite different things, and they have very different value profiles. Keeping them separate is essential to answering the question honestly.

| | Vocabulary | Diagnosis |
| --- | --- | --- |
| **What it does** | Supplies names and distinctions for discussion | Places a specific person in a specific position |
| **Requires validation?** | No. A word is useful or it is not | Yes. Absolutely |
| **Failure mode** | Falls out of use | Someone is mislabelled with consequences |
| **Value if the model is wrong** | Possibly still positive — the distinctions may be useful even if the graph is not | Negative |
| **Currently supported?** | Yes | No |

Nearly all of the model's defensible value sits in the left column. Nearly all of the effort in the design set — the graph, the transitions, the attributes, the classifier — sits in the right.

**That mismatch is the central finding of this audit**, and it is developed in [02-component-audit.md](02-component-audit.md).

## What this audit cannot settle

Honesty requires stating the limits of the assessment itself.

- **It is conducted by parties with a stake in the answer.** The author has invested substantial work; an assistant asked to evaluate that work faces an obvious pull toward finding it valuable. Both should be discounted accordingly.
- **No user has been observed.** Every scenario in these documents is constructed. Constructed scenarios favour the framework being assessed, because they are written by someone who knows what it can do.
- **The counterfactuals are guesses.** What a manager would have done without the model is not observable, and the estimate will tend to be generous to the model.

The correction for all three is the same and it is cheap: **give the material to a handful of practitioners and see whether any of them come back to it.** That single observation would be worth more than this entire audit, and it is the basis of the stopping rule in [09-verdict.md](09-verdict.md).
